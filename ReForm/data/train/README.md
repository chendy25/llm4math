# ReForm SFT Training Data Collection

This directory contains code to **generate SFT (supervised fine-tuning) training data** for ReForm, following the pipeline described in the paper (Appendix A.1): multi-agent style trajectory collection with autoformalization, optional Lean verification, and semantic consistency checking.

## Pipeline (Paper A.1)

1. **Initial Autoformalization**: Generate Lean4 formal statement from natural language (prompt D.1).
2. **Syntactic Validation** (optional): Verify the statement compiles in Lean4 (`VERIFY_URL` / `VERIFY_KEY`).
3. **Semantic Consistency Evaluation**: LLM judges whether the formalization is semantically faithful (prompt D.2).
4. **Reflective Refinement**: If inconsistent, feed back failure + critique and regenerate (D.1 with history).
5. **Iteration**: Repeat until consistent, or max rounds (default 3).

The collected trajectory is then formatted as a single **ReForm-style response** (<think> + `<round>...</round>` blocks + `<answer>...</answer>`) and saved as SFT samples with `messages` for use with slime (`--input-key messages`).

## Files

| File | Description |
|------|-------------|
| `prompts.py` | Prompts from paper Appendix D.1 (autoformalization), D.2 (consistency check), D.4 (ReForm instruction). Adds a tool-augmented system prompt variant. |
| `llm_client.py` | OpenAI-compatible API client; extracts Lean4 blocks, parses consistency XML, and runs the agentic tool loop (`autoformalize_with_tools`). |
| `leansearch_tool.py` | Standalone, dependency-light LeanSearch-v2 `/search` tool (client + result formatter + tool-call parse/exec). Reusable by a future RL rollout. |
| `verify_lean.py` | Optional Lean 4 verification (uses `VERIFY_URL` / `VERIFY_KEY` if set). |
| `trajectory_builder.py` | Builds the final assistant response in ReForm format. |
| `collect_sft_trajectory.py` | One-problem pipeline: autoformalize (optionally with LeanSearch tool) → (optional verify) → consistency → refine loop. |
| `run_collect_sft_data.py` | CLI: load JSON/JSONL → collect trajectories → write `sft_data.jsonl`. |

## LeanSearch tool integration (autoformalization)

When `--use-leansearch` is set, the autoformalization step becomes an agentic
ReAct loop: the teacher model may query [LeanSearch-v2](https://leansearch.net)
to retrieve real Mathlib declarations (names, signatures, informal descriptions)
before committing to a formal statement, reducing hallucinated lemma names.

The tool call is recorded **inline** inside the single assistant message (keeping
the ReForm/slime trajectory format). The model emits:

```
<tool_call>
{"name": "leansearch", "arguments": {"query": "order of a group element divides the order of the group", "num_results": 8}}
</tool_call>
```

and the harness injects the retrieved declarations:

```
<tool_response>
[1] orderOf_dvd_card : orderOf x ∣ Fintype.card G
    The order of an element divides the cardinality of the group.
...
</tool_response>
```

These blocks live inside the `<round>...</round>` of the autoformalization phase
(the semantic-consistency phase is unchanged). Tool usage is bounded by
`--max-tool-calls` per autoformalization step.

### Run with the tool

```bash
python run_collect_sft_data.py \
    --input ../test/test.json --output sft_data.jsonl --max-items 1 \
    --use-leansearch \
    --leansearch-url https://leansearch.net \
    --leansearch-top-k 8 \
    --max-tool-calls 3
```

Each output record gains a `num_tool_calls` field.

### Note on SFT loss masking

The `<tool_response>...</tool_response>` content is injected by the environment,
not generated by the model. For best results the training data loader should
**mask the loss** over those spans (so the model is not trained to "predict"
retrieval output). The MVP keeps everything in one assistant message for format
simplicity and does not emit explicit mask spans; adding tag-based masking in the
SFT loader (slime / verl side) is recommended as a follow-up.

### Reuse in RL

`leansearch_tool.py` has no dependency on the data-collection code, so a future
RL rollout (e.g. verl) can `import leansearch_tool` and reuse
`parse_tool_call` / `run_tool_call` / `format_results` directly.

## Usage

### 1. Environment

- **LLM API**: OpenAI-compatible server (vLLM, SGLang, or remote). Set:
  - `OPENAI_BASE_URL` (e.g. `http://127.0.0.1:8000/v1`)
  - `OPENAI_API_KEY` (e.g. `EMPTY` for local)
- **Lean (optional)**: For syntactic verification, run a Kimina Lean Server and set:
  - `VERIFY_URL` (e.g. `http://127.0.0.1:8000`)
  - `VERIFY_KEY` (must match server `LEAN_SERVER_API_KEY`)
  - Local client shim: `ReForm/leanclient` (no separate `leanclient` pip package needed).

### 2. Input format

Input JSON or JSONL must provide **informal statements** per item, e.g.:

- `informal_statement`: natural language math problem (required)
- Optional: `dataset_name`, `question_id`, etc. (copied to output)

Example `test.json`:

```json
{"dataset_name": "aime2025", "question_id": "1", "informal_statement": "Find the sum of all integer bases $b>9$ for which ..."}
```

### 3. Run collection

From this directory (`data/train`):

```bash
# Use test set (e.g. one item)
export OPENAI_BASE_URL=http://127.0.0.1:8000/v1
export OPENAI_API_KEY=EMPTY
python run_collect_sft_data.py --input ../test/test.json --output sft_data.jsonl --max-items 1
```

Options:

- `--input`, `-i`: Input JSON or JSONL path (default: `../test/test.json`).
- `--output`, `-o`: Output JSONL path (default: `sft_data.jsonl`).
- `--max-items`: Cap number of problems (default: all).
- `--use-lean-verify`: Enable Lean syntactic verification.
- `--max-rounds`: Max refinement rounds per problem (default: 3).
- `--use-leansearch`: Enable the LeanSearch retrieval tool during autoformalization.
- `--leansearch-url`: LeanSearch `/search` endpoint (default: `https://leansearch.net`).
- `--leansearch-top-k`: Default `num_results` per query (default: 8).
- `--max-tool-calls`: Max tool calls per autoformalization step (default: 3).
- `--model`: Model name for API (default: `default`).
- `--base-url`: Override `OPENAI_BASE_URL`.

### 4. Output format

Each line of the output JSONL is one SFT sample, e.g.:

```json
{
  "messages": [
    {"role": "user", "content": "Think step by step to translate the mathematical problem in natural language to Lean 4, and verify the consistency.\n\n<informal_statement>"},
    {"role": "assistant", "content": "<think>\n...<round>...</round>...</think>\n\n<answer>\n```lean4\n...\n```\n</answer>"}
  ],
  "informal_statement": "...",
  "num_rounds": 2,
  "success": true,
  "dataset_name": "aime2025",
  "question_id": "1"
}
```

Use this file as `--prompt-data ./data/train/sft_data.jsonl` with `--input-key messages` in slime SFT scripts.
